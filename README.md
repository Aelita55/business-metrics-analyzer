## Ответы на вопросы
### 1. Чем отличается Git от GitHub?
Git — это программа, которая работает локально на компьютере и отслеживает изменения в файлах
GitHub — это облачный сервис, где хранятся Git-репозитории. Он позволяет команде работать вместе, делать ревью кода и управлять проектом.
### 2. Для чего используется виртуальное окружение Python?
Для изоляции библиотек конкретного проекта. Это гарантирует, что проект будет стабильно работать на любом компьютере с нужными версиями пакетов, не конфликтуя с другими проектами на этом же ПК
### 3. Что такое commit, branch, remote, pull request?
Commit - это точка сохранения изменений в коде с описанием 
Branch - изолированная линия разработки, чтобы экспериментировать, не ломая основную рабочую версию (main)
Remote - ссылка на удалённый репозиторий куда отправляются (push) и откуда скачиваются (pull) изменения.
Pull Request - запрос на слияние изменений из одной ветки в другую с возможностью проверки кода коллегой перед объединением
### 4. Зачем нужен файл  .gitignore?
Чтобы Git игнорировал и не загружал в репозиторий временные файлы, кэш, секретные данные, экономит место
### 5. Как организовать командную работу над бизнес-приложением с помощью Git?
Через систему ветвления: основная ветка main всегда стабильна. Новые функции разрабатываются в отдельных ветках, затем создаётся Pull Request, код проверяется коллегой, и только после одобрения изменения сливаются в main
### 6. Какие файлы обязательно должны быть в репозитории учебного проекта?
Исходный код main.py
Файл зависимостей requirements.txt
Описание проекта и инструкция по запуску README.md
Файл исключений .gitignore
### 7. Что произойдёт, если два разработчика изменят один и тот же файл в разных ветках?
При попытке слияния возникнет конфликт слияния. Git не сможет автоматически решить, чья версия правильная, остановит процесс и попросит разработчиков вручную отредактировать файл, выбрав нужный код или объединив оба варианта.
