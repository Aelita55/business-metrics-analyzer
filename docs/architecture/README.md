# Архитектура Business Metrics Analyzer

## 1. Обзор системы

**Business Metrics Analyzer (BMA)** — веб-приложение для загрузки данных о продажах, расчёта KPI и визуализации бизнес-метрик торговой компании.

Роли пользователей: коммерческий директор, менеджер по продажам, аналитик, администратор.

**Границы системы:**
- BMA не является учётной системой и не заменяет 1С;
- данные о продажах поступают из внешних источников: 1С, CSV/Excel, API;
- система отвечает за импорт, хранение, расчёт KPI, дашборды, отчёты, разграничение доступа и аудит действий.

**Ключевые функциональные области:**
1. Аутентификация и управление пользователями.
2. Импорт данных о продажах.
3. Расчёт KPI: выручка, средний чек, конверсия, рентабельность.
4. Визуализация и дашборды.
5. Формирование и экспорт отчётов в Excel/PDF.
6. Настройка метрик и справочников.
7. Логирование и аудит действий.

## 3. Выбранный архитектурный стиль

Выбран **слоистый монолит с элементами Clean Architecture**.

**Обоснование:**
- команда проекта небольшая — 3–4 человека;
- требуется быстрый MVP;
- бизнес-логика должна быть изолирована от инфраструктуры;
- слоистая структура упрощает тестирование и сопровождение;
- при росте нагрузки возможен постепенный переход к микросервисам, начиная с сервисов импорта и отчётов.

**Слои:**
1. **Presentation** — FastAPI-контроллеры, DTO, валидация HTTP-запросов.
2. **Application** — сервисы бизнес-сценариев.
3. **Domain** — модели предметной области, стратегии KPI, валидаторы.
4. **Infrastructure** — репозитории, Unit of Work, JWT, генераторы отчётов, интеграции.

## 5. Слои и компоненты

| Слой | Компоненты | Ответственность |
|---|---|---|
| Presentation | AuthController, SalesController, KpiController, ReportsController | Обработка HTTP-запросов, валидация DTO, формирование ответов |
| Application | AuthService, UserService, SalesImportService, KpiService, ReportService | Реализация бизнес-сценариев и оркестрация доменных операций |
| Domain | Sale, Kpi, User, Report, KpiStrategy, Validators | Бизнес-правила, расчёт метрик, инварианты |
| Infrastructure | SqlSaleRepository, SqlUserRepository, UnitOfWork, JwtProvider, ExcelReportGenerator, EmailNotifier | Доступ к БД, транзакции, аутентификация, экспорт, интеграции |

**Ключевые интерфейсы:**
- IKpiService: calculate_period(period) -> KpiResult, get_dashboard(period) -> DashboardDto;
- ISalesImportService: import_csv(file) -> ImportResult, validate(records) -> ValidationResult;
- IReportService: generate(report_type, period) -> ReportFile, export_excel(report_id) -> bytes.

## 6. Используемые паттерны

Подробное обоснование: ./patterns.md.

| Паттерн | Где применяется | Краткое обоснование |
|---|---|---|
| Repository | Доступ к данным о продажах и пользователях | Изоляция бизнес-логики от SQLAlchemy |
| Unit of Work | Импорт данных, транзакции | Атомарность операций и откат при ошибках |

| DTO | API-контракты | Чёткие контракты и версионирование API |
| Adapter | Интеграция с 1С, SMTP, S3 | Изоляция внешних зависимостей |
| Observer | Обновление дашборда | Реакция на изменение данных |

## 8. Ограничения и компромиссы

- Выбран монолит, поэтому горизонтальное масштабирование ограничено по сравнению с микросервисами.
- Для соблюдения времени отклика дашборда ≤ 3 с используется кэширование KPI и предрасчёт агрегатов.
- Импорт до 1 млн записей выполняется асинхронно и чанками, чтобы не блокировать API.
- JWT выбран для MVP, но при необходимости можно добавить refresh-токены и внешний identity provider.
- Redis является опциональным компонентом: при отказе кэша система должна продолжать работать с PostgreSQL.
- Выделение сервисов импорта и отчётов отложено до этапа масштабирования.

## 9. План развития архитектуры

1. Выделить сервис импорта данных в отдельный worker/сервис.
2. Вынести сервис отчётов и файловое хранилище в отдельный компонент.
3. Добавить очередь сообщений для асинхронных задач.
4. Ввести материализованные представления или отдельное KPI-хранилище.
5. При росте команды и нагрузки рассмотреть переход к микросервисам.
6. Добавить централизованный мониторинг, трассировку и алертинг.
