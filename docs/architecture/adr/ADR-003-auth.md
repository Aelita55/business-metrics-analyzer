# ADR-003. Выбор способа аутентификации

## Статус

Принято.

## Контекст

В системе предусмотрены роли: директор, менеджер, аналитик, администратор. Требуется разграничение доступа к данным и функциям. Приложение является веб-приложением с REST API.

## Решение

Выбрана аутентификация на основе JWT.

Реализация:
- выдача access-токена после логина;
- проверка токена в AuthService / JwtProvider;
- роли и права передаются в токене или загружаются из БД;
- для MVP допускается короткоживущий access-токен без refresh-токена.

## Альтернативы

1. Сессионная аутентификация — проще для монолита, но требует хранения сессий и хуже подходит для API-клиентов.
2. OAuth2 / внешний identity provider — избыточно для MVP, но может быть добавлено позже.
3. Basic Auth — небезопасно для production без дополнительных мер.
4. API-ключи — подходят для сервисных интеграций, но не для пользовательских ролей.

## Последствия

Плюсы:
- stateless-аутентификация;
- удобство для REST API;
- возможность масштабирования;
- гибкое разграничение ролей.

Минусы:
- необходимость аккуратной работы с секретами и сроком жизни токена;
- при компрометации токена нужна стратегия отзыва;
- для production желательно добавить refresh-токены и rotation.
