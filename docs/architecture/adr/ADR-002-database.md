# ADR-002. Выбор СУБД

## Статус

Принято.

## Контекст

Система должна хранить данные о продажах, пользователях, метриках, KPI, отчётах и аудите действий. Объём данных — до 1 млн записей о продажах. Требуются транзакционность, индексы, агрегации и надёжность.

## Решение

Выбрана PostgreSQL.

Основные причины:
- надёжная транзакционная СУБД;
- поддержка индексов и сложных аналитических запросов;
- хорошая интеграция с SQLAlchemy;
- возможность использовать JSONB для гибких атрибутов;
- бесплатность и распространённость;
- удобное развёртывание в Docker.

## Альтернативы

1. SQLite — прост в разработке, но плохо подходит для конкурентного доступа и production-нагрузки.
2. MySQL — допустимый вариант, но PostgreSQL удобнее для аналитических запросов и расширений.
3. MongoDB — гибкая схема, но менее удобна для транзакционных и агрегационных сценариев с KPI.
4. ClickHouse — хорош для аналитики, но избыточен для MVP и требует отдельной экспертизы.

## Последствия

Плюсы:
- надёжное хранение транзакционных данных;
- поддержка сложных запросов и агрегаций;
- возможность масштабирования и репликации;
- единый стек с SQLAlchemy.

Минусы:
- требуется администрирование БД;
- для очень больших аналитических нагрузок в будущем может потребоваться отдельное хранилище или materialized views.
